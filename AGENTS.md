# AGENTS.md

This file provides guidance to agents when working with code in this repository.

## Repository Structure

Four sub-projects — each must be run from its own directory:

| Sub-project | Language | Purpose |
|---|---|---|
| `Metallisense-Agent/` | Python 3.11 / FastAPI | Agent+Copilot layer — port **8001** |
| `Metallisense-AI/` | Python 3.11 / FastAPI | Base ML layer — port **8000** |
| `MetalliSense-Node-Backend/` | Node.js / Express | API gateway + MongoDB + OPC UA — port **3000** |
| `Metallisense-frontend/` | React 19 / Vite | React SPA — auth via Firebase |

## Commands

### Metallisense-Agent (Python)
```powershell
# One-time setup + train models
cd Metallisense-Agent
python -m venv venv; venv\Scripts\activate
pip install -r requirements.txt
python setup.py            # generates data, trains both models, verifies

# Start API (port 8001)
python app/main.py

# Retrain only
python retrain_models.py

# Run integration test (API must be running on localhost:8000)
python test_agent_system.py

# Run individual module tests (no server needed)
python app/data/grade_specs.py
python app/inference/anomaly_predict.py
python app/training/train_anomaly.py
python app/training/train_alloy_agent.py
```

### Metallisense-AI (Python)
```powershell
cd Metallisense-AI
python -m venv venv; venv\Scripts\activate
pip install -r requirements.txt
python setup.py            # train models for the base ML layer
python app/main.py         # start API on port 8000
```

### MetalliSense-Node-Backend (Node.js)
```powershell
cd MetalliSense-Node-Backend
npm install
# Config file is config.env (not .env) — required before start
npm start                  # nodemon server.js
npm run test:gemini        # integration test for Gemini service
npm run seed               # seed MongoDB
```

### Metallisense-frontend (React/Vite)
```powershell
cd Metallisense-frontend
npm install
npm run dev                # Vite dev server
npm run build
npm run lint               # eslint
```

## Critical Non-Obvious Rules

### Python path pattern — every module does this
Every Python file that imports from sibling directories uses:
```python
sys.path.append(str(Path(__file__).parent.parent))
```
This is required because there is no installed package — do not remove it.

### Models are `.pkl` files under `app/models/` — not committed
`anomaly_model.pkl` and `alloy_model.pkl` are generated by training scripts and live at:
- `Metallisense-Agent/app/models/`  
- `Metallisense-AI/app/models/`

The API raises `FileNotFoundError` at startup if models are absent. Run `setup.py` first.

### Anomaly training uses only tightly filtered normal samples
`train_anomaly.py` filters out deviated samples **and** also drops normal samples outside 1.5σ per element. Training on the full normal set produces worse sensitivity. Do not change this filtering.

### Alloy agent only fires on MEDIUM or HIGH severity
`DecisionPolicy.should_recommend_alloy()` returns `False` for LOW/NORMAL. The alloy agent always appears in the response but its `recommended_additions` will be `{}` when skipped.

### Agent response contract — required fields
`DecisionPolicy.validate_agent_response()` checks for `["agent", "confidence", "explanation"]` and that `response["agent"] == agent_name`. Missing any of these fields causes a validation failure logged to stdout (not raised as an exception).

### Node backend config file is `config.env`, not `.env`
`server.js` calls `dotenv.config({ path: './config.env' })`. A standard `.env` file is ignored.

### Frontend auth is Firebase ID token in `Authorization: Bearer`
`src/services/api.js` attaches a fresh Firebase ID token on every request. The Node backend validates it via `firebase-admin`. There is no separate JWT system.

### Two AI service URLs in Node backend
`services/aiService.js` has `AI_SERVICE_INDIVIDUAL_URL` (individual endpoints) and `AI_SERVICE_AGENT_URL` (agent endpoint). Both default to `http://localhost:8000`. The Agent service is actually on **8001** — set these env vars appropriately.

### PASS/FAIL is NOT decided by AI
The Node.js rule engine determines PASS/FAIL. The Python AI services are advisory only. Do not add autonomous actions to the Python layer.

### Grade specifications are hardcoded in `grade_specs.py`
`GradeSpecificationGenerator` builds specs in `_generate_specifications()` — not loaded from a file. Supported grades: `SG-IRON`, `GREY-IRON`, `LOW-CARBON-STEEL`, `MEDIUM-CARBON-STEEL`, `HIGH-CARBON-STEEL`. Adding a new grade requires editing this method AND retraining the alloy model.

### Groq API key is required for Copilot features
`GROQ_API_KEY` env var must be set for `/copilot/*` and `/copilot/voice/*` endpoints. The core ML endpoints (`/agents/analyze`, `/anomaly/predict`, `/alloy/recommend`) work without it.

## Code Style

- Python: type hints on all function signatures; docstrings on all public methods; `Dict`, `Optional` from `typing` (not built-in generics)
- Singleton pattern via module-level `_instance = None` + `get_X()` factory functions — used for agents, predictors, copilot, and voice service
- Error handling in agents returns a structured dict (never raises) so the manager always gets a response
- Node.js: CommonJS (`require`/`module.exports`); no TypeScript; ESLint + Prettier configured
- Frontend: `.jsx` files; React 19; Tailwind CSS; no test framework present
